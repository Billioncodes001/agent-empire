# Design requirements for the next city phase

User instruction received 2026-09-27; checked against the master `~/.claude/PAI/USER/WEB_DESIGN_STANDARD.md`. The master wins if this project interpretation differs. These requirements accompany every future interface/world assignment.

- **Art direction and research:** inspect leading simulation/game interfaces and motionsites.ai before designing. Adapt motion/composition ideas; never copy their code or assets. Maintain a consistent realistic architectural, character, material, lighting and audio vocabulary across districts, interiors, vehicles and phone UI. Avoid generic template styling.
- **Motion and depth:** use Three.js and appropriate animation/postprocessing tools for real 3D scenes. Make phone opening, camera transitions, menus, calls, garages and vehicle boarding feel continuous and responsive. The user permits installing libraries that the design needs. Respect the existing renderer rather than adding competing animation loops without a reason.
- **Custom media:** use Higgsfield when suitable for imagery/video; the user authorizes credits. Reuse palette and stills across a sequence. For cinematic loops, use matching start/end frames, MP4 plus WebM and a poster, lazy loading and off-screen pause. Generated videos are presentation assets, not a substitute for controllable skeletal vehicle/character animation.
- **Simple interaction:** plain labels, one obvious next action, auto-detected local services and microphones where available, prefilled known values, short setup steps, Test connection, Test microphone and Preview voice. Provide Simple/Expert views and platform-specific instructions for technical setup. Permission-denied/missing-model/busy-host states need understandable recovery and text fallback.
- **Performance/accessibility:** make the launcher/loading UI usable before heavy assets load; stream/lazy-load expensive scenery and media. Honor reduced-motion and Save-Data, visible focus, semantic controls, contrast and non-color status cues. Preserve readable text equivalents for animated text and captions for spoken output. Retain low/medium/high graphics and measure frame times before expanding effects.
- **Responsive verification:** check desktop and 375px phone width without horizontal overflow. Exercise keyboard, touch-sized targets and modal focus; capture both screenshots and check console errors before claiming UI completion. Flight/voice/vehicle acceptance also needs interactive runtime checks.
- **Public web surfaces:** when a public landing/help site is built, include crawlable primary copy, appropriate titles/descriptions/canonicals, structured data, sitemap/robots, llms.txt, OG imagery and FAQs. Keep protected worker/project data out of public crawlable pages.
- **Commercial tiers, if introduced:** apply the user's teaser, visible locks and benefit-led upgrade design with server-enforced entitlements and durable trial-abuse protection. No pricing tier or paywall has been introduced by this planning pass.

This adds requirements to the recorded roadmap; it does not claim that the existing prototype or future features already satisfy them.
