### Shared

1. **Cloud mode only adds.** The office server's chief and outreach behave exactly as before. Rules that both sides apply move to `src/shared/` and are re-exported unchanged, as FREE-07 did. A test asserts the server and the coordinator call the identical functions.
2. **The coordinator stays the only writer of `state/`.** Clients send intents with strict allow-lists: every new kind lists its exact fields, and unknown fields are refused.
3. **No secret value is ever set, read, stored or relayed by the Empire.** The user stores keys and the SMTP URL as Actions secrets in their own state repository. The game checks only that the secret's name exists (`GET /repos/{o}/{r}/actions/secrets`, the FREE-04 pattern), and has no field that could take a value.
4. **Capability matrix and UI messages** are updated, and every remaining gap keeps a specific reason.
5. **Tests:** failing first, with fake GitHub, a fake model provider and a fake SMTP transport. No real network, dispatch, model call or email.

### FREE-11: the chief's planning brain in cloud

6. **Where it runs:** inside the coordinator's tick job on GitHub Actions. The coordinator is our own bundle; model output there is only ever data that is parsed strictly. No agent code runs in that job.
7. **Backends:**
   - **Free (opt-in):** a hosted free tier with the user's own key: OpenRouter (`OPENROUTER_API_KEY`), Gemini (`GEMINI_API_KEY`) or Groq (`GROQ_API_KEY`). The provider's data-use terms (`HOSTED_FREE`) are shown, and must be acknowledged, before it can be enabled. US$0, but capped in calls per day.
   - **Premium:** `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`, with a configured price per million tokens.
   - **Never** a Claude subscription token (`CLAUDE_CODE_OAUTH_TOKEN`) and never `claude -p`. A test asserts the brain has no such path and the tick job's environment holds no such secret.
   - Ollama is not offered in cloud: GitHub-hosted runners have none. The matrix says so.
8. **Money safety**, enforced by the coordinator and persisted in the state repository **before** any call:
   - The worst case (an input-token bound plus `max_tokens`, at the configured price) is charged first.
   - A **daily cap** (UTC day, default $2 as in FREE-02) and a **monthly cap** (default $20, applied to a **rolling 30-day** sum so a month boundary never resets it). Both are CEO-editable through an intent. A call is refused if its worst case would pass either cap.
   - A **rolling 30-day spend log** of every charge.
   - If the pre-charge commit fails, no call is made: the call happens only after the commit that holds the charge succeeded, and only for charges that name this run.
   - The charge is replaced with the actual cost only when the provider reports usage. Otherwise, and whenever the call fails, the worst case stays.
   - A zero price is refused, and so is premium without a price.
9. **Time sources:** the clock for the caps is GitHub's, not the runner's alone:
   - The coordinator reads its own run's `run_started_at` from the Actions API (server time; a re-run attempt has its own).
   - The brain's clock is monotonic: `max(GitHub time, last recorded charge time)`. A replayed or old run can never land in an earlier day.
   - If GitHub's time can't be read, or the runner's clock differs from it by more than 15 minutes, no paid call is made in that run.
10. **Replay and re-run safety:** each request moves `queued → charged(runId) → done | needs_attention`, committed. A `charged` request left by another run (crash, cancelled run, re-run attempt) becomes `uncertain`: its charge stays and it is never called again. The commit's compare-and-swap means two runs can never both charge the same request.
11. **Output stays proposals:**
    - **Plans:** the CEO writes a brief in the game. The answer goes through the strict FREE-02 plan schema and screens (the shared `parsePlan`, invisible-character and heuristic filters, lesson ids limited to the ones given) and becomes a `job_plan` inbox item with every prompt shown. Approving records the decision only; each item is then submitted, if the CEO wants, through the existing paid-job confirmation (`new_job` with `confirmPaid` and the current `configRevision`).
    - **Reviews** of finished cloud jobs and **unblock** suggestions for failed or uncertain ones become `chief_proposal` items. Deciding records the decision only; nothing accepts a job or moves credits.
    - Malformed or unsafe output is needs-attention with the reason; nothing is guessed.
    - Approved lessons from the FREE-07 cloud memory are given to the plan as a delimited data block, and the plan's citations are checked against them.
12. **Prompt injection:** briefs, job evidence and lessons are untrusted data between random per-call markers, with the same rules text as the server.

### FREE-12: outreach email in cloud

13. **Secrets:** the SMTP URL (with its password) is the Actions secret `AGENT_EMPIRE_SMTP_URL` in the state repository. Names are checked only. The sender identity (from address, display name, postal address) is not secret: it is stored in state and printed in every footer.
14. **Every send needs the CEO's approval of the exact message and recipients** (`external_action`): the coordinator freezes a snapshot (subject, body, fixed footer, sender, every recipient, caps) and raises one item whose fingerprint covers it. Any change resolves the item and raises a new one.
15. **Compliance**, as on the server: the fixed footer with the postal address and the STOP line; honest sender identity; one message per recipient, never CC or BCC; a suppression list checked when the snapshot is frozen **and** again right before each send; daily caps.
16. **Pacing:** the coordinator runs every 15–60 minutes, so sends are capped **per run** (default 20) and **per UTC day** (default 50). The game shows the expected delivery honestly: how many runs and roughly how long, given the schedule.
17. **At most once:** before a run sends anything, the tick job claims that run's batch in a commit. The send job sends only the batch claimed by its own run id and writes a receipt. A claim without a receipt becomes `uncertain` and is never re-sent.
18. **Privacy:**
    - Leads and suppression live in the user's private state repository and its git history. A warning at setup must be acknowledged before anything is stored.
    - Store the minimum: email, name, company and tags per lead. Suppression is stored only as salted SHA-256 hashes. The game hashes an opt-out before sending it, so the plain address never reaches the repository through that path. A suppressed lead is removed from the lead list. A finished campaign keeps counts, not addresses.
    - "Delete lead data" writes a commit that removes every lead and every stored recipient address (campaign snapshots and inbox items). The UI says plainly that git history keeps old versions unless the user rewrites history themselves.
19. **Isolation (FREE-04 lesson):** sends happen in a separate `send` job of the coordinator workflow. It holds `AGENT_EMPIRE_SMTP_URL` and no model key, runs only our `send` command, and runs no model or agent code. The tick job, where model output is parsed, holds no SMTP secret. Message content is validated for header injection and size when the campaign is written, when the snapshot is frozen, and again in the send job.

## Design

### FREE-11: the brain (`src/cloud/brain.ts`, `src/cloud/brain-call.ts`)

- **State:** the optional file `state/brain.json` holds the settings, a spend log of the last 30 days, and requests (`queued → charged → done | needs_attention | uncertain`). If it can't be read, it is quarantined like `org.json`: left untouched, with its intents refused.
- **The tick:**
  - **Commit 1:**
    1. A charge left by another run becomes `uncertain`.
    2. Up to 2 queued requests are charged at their worst case: `inputTokenBound × input price + max_tokens × output price`, in micro-dollars, rounded up.
    3. The charge must fit both the daily cap (UTC day) and the cap for the last 30 days. A free tier is US$0, but has a cap on calls per day.
    4. All of this is committed.
  - **Model calls:** made only if that commit landed, and only for requests charged by this run in the committed state.
  - **Commit 2:** the answers are recorded. When usage is reported, its cost at the configured price replaces the worst case. A failed call keeps the worst case.
- **Clock:** the coordinator reads its own run's `run_started_at` from the Actions API, which is GitHub's time; a re-run attempt has its own. The charge clock is the larger of that time and the last recorded charge. There is no paid call when GitHub's time is missing, or when the runner's clock is more than 15 minutes off.
- **Replays and re-runs:**
  - The run id is `<run id>-<attempt>`, so a re-run attempt can never call for an earlier attempt's charge.
  - The commit's compare-and-swap stops two runs from charging the same request.
- **Output:**
  - The shared FREE-02 parsers and screens (`src/shared/chief-rules.ts`, which the server re-exports) decide what is accepted. Plans become `job_plan` items carrying a `plan` (every prompt, the lessons given, and the ids the plan cites, which must be among them). Reviews and unblock ideas become `chief_proposal` items.
  - A plan's prompts are in its item's fingerprint. They are added only when a plan is present, so existing fingerprints don't change.
  - Malformed or unsafe answers need attention, with the parser's reason.
- **Keys:** `brainKeysFromEnv` reads only the five provider key names. The tick job gained `OPENROUTER_API_KEY`, `GEMINI_API_KEY` and `GROQ_API_KEY`; `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` were already there. Nothing reads `CLAUDE_CODE_OAUTH_TOKEN`, and `claude -p` is not used.

### FREE-12: outreach (`src/cloud/outreach.ts`, `src/cloud/outreach-send.ts`)

- **State:** the optional file `state/outreach.json` holds:
  - the sender (from, name, postal address), the caps per run and per day, and when the privacy warning was acknowledged;
  - leads (email, name, company, tags);
  - opt-outs as `sha256(salt:email)`. The salt is per Empire, and the game hashes the address before sending it;
  - campaigns with a frozen snapshot and a status per recipient;
  - claims per UTC day.
- **Approval:**
  - Each tick, every draft is frozen into a snapshot: subject, body, fixed footer, sender, recipients and caps, hashed with SHA-256.
  - The snapshot raises one `external_action` item. Any change resolves the old item and raises a new one.
  - A decision is checked against the campaign's snapshot before it applies.
- **Pacing, at most once:**
  1. Commit 1 consumes the receipts, freezes drafts and claims this run's batch: at most the per-run cap, within the daily cap. Suppression is checked again here.
  2. The send job, in the same workflow run (`needs: tick`), sends only the claims that name its run id and writes `outbox/receipts/<run id>.json`.
  3. The next tick applies that receipt. A claim without a result becomes `uncertain` and is never sent again.
  4. A send job without the SMTP secret records that it attempted nothing. Its claims are released, and the campaign says why.
- **Isolation:** the `send` job holds only `AGENT_EMPIRE_SMTP_URL` and `GITHUB_TOKEN`. It runs only `agent-empire-coordinator.mjs send` and executes no model or agent code. The tick job holds no SMTP secret.
- **Validation:** `checkCampaignText` (shared) refuses control characters in the subject, encoded words, HTML, unknown merge fields, hidden characters, and oversized bodies or lines. It runs when the intent arrives, when the snapshot is frozen, and in the send job, which also checks the sender, the recipient, the footer and suppression again.
- **Privacy:**
  - Suppressed and finished recipients' addresses are removed from the campaign and from the inbox items.
  - "Delete lead data" removes every lead and stored address in one commit, keeps the opt-out hashes, and resolves pending sends.
  - The UI says that git history keeps old versions.

- `src/shared/email-address.ts`: `isEmailAddress`, `normalizeEmail`.

### Game

- The chief's card opens **the chief's brain** panel. It shows the settings, the provider's terms with an accept box, the price with a paid confirmation, both caps, the spend so far, a secret-name check, plan requests, reviews and unblock ideas, and recent requests.
- The marketing card opens **outreach**. It shows the privacy warning and its acknowledgement, the sender, the caps, the SMTP secret-name check, campaigns with their expected delivery, leads, opt-outs (hashed on the device), and "Delete lead data" with a confirmation.
- The inbox shows a cloud plan with every prompt and records the decision only. Once approved, each item has "Submit item N as a cloud job…", which opens the existing paid confirmation. A campaign send shows the cloud pace.
- Both panels and the inbox show only what the coordinator recorded. A secret-name check reads names, never values.

## Deferred / not verified

- **No real GitHub run, model call or email.** Unverified against the real services:
  - `GET /repos/{o}/{r}/actions/runs/{id}` → `run_started_at`;
  - the OpenAI-compatible endpoints of OpenRouter, Gemini, Groq and OpenAI, and Anthropic's OpenAI-compatibility layer with a Bearer key (the same path the server's `llm.ts` uses);
  - the SMTP send from an Actions runner. Some providers block runner IP ranges, and port 25 is usually closed, so use 587 or 465.

  A first real run should take one premium plan with a $0.50 cap, then one campaign to the owner's own address.
- **Existing Empires need the new coordinator workflow** (the send job and the free-tier key variables). The coordinator bundle and workflow are shipped as before; this slice adds no automatic workflow upgrade.
- **The brain runs inside the coordinator tick job,** which has an 8-minute timeout. Two calls of up to 90 s each fit, but a slow provider can make a run take longer.
- **Model-proposed lessons are ignored in cloud mode:** the prompts don't ask for them, and any that appear are discarded.
- **Not done in cloud mode:**
  - automatic reviews or stall proposals (the chief answers only when asked);
  - bounce handling that suppresses addresses (550 responses);
  - a `List-Unsubscribe` header;
  - worker-drafted campaigns;
  - a Telegram `/optout`.
- **Re-runs of the send job:** a manual "re-run failed jobs" gets a new attempt id and sends nothing. The claims of the failed attempt become uncertain, which is safe but means those messages are never sent.
- **Not checked separately:** phone checks used Chrome emulation, not a real device; Save-Data and a full keyboard walk of the two new panels.
- **Overlap with the city-architect integration:** `src/client/ui/inbox.ts` gained the cloud plan block and cloud-mode copy, and `src/shared/approvals.ts` gained `plan` and `perRun`. Both merged cleanly with CITY-10.
