### Shared

1. **Cloud mode only adds.** The office server's chief and outreach behave exactly as before. Rules that both sides apply move to `src/shared/` and are re-exported unchanged, as FREE-07 did. A test asserts the server and the coordinator call the identical functions.
2. **The coordinator stays the only writer of `state/`.** Clients send intents with strict allow-lists: every new kind lists its exact fields, and unknown fields are refused.
3. **No secret value is ever set, read, stored or relayed by the Empire.** The user stores keys and the SMTP URL as Actions secrets in their own state repository. The game checks only that the secret's name exists (`GET /repos/{o}/{r}/actions/secrets`, the FREE-04 pattern), and has no field that could take a value.
4. **Capability matrix and UI messages** are updated, and every remaining gap keeps a specific reason.
5. **Tests:** failing first, with fake GitHub, a fake model provider and a fake SMTP transport. No real network, dispatch, model call or email.

### FREE-11: the chief's planning brain in cloud

6. **Where it runs:** inside the coordinator's tick job on GitHub Actions. The coordinator is our own bundle; model output there is only ever data that is parsed strictly. No agent code runs in that job.
7. **Backends:**
   - **Free (opt-in):** a hosted free tier with the user's own key: OpenRouter (`OPENROUTER_API_KEY`), Gemini (`GEMINI_API_KEY`) or Groq (`GROQ_API_KEY`). The provider's data-use terms (`HOSTED_FREE`) are shown, and must be acknowledged, before it can be enabled. US$0, but capped in calls per day.
   - **Premium:** `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`, with a configured price per million tokens.
   - **Never** a Claude subscription token (`CLAUDE_CODE_OAUTH_TOKEN`) and never `claude -p`. A test asserts the brain has no such path and the tick job's environment holds no such secret.
   - Ollama is not offered in cloud: GitHub-hosted runners have none. The matrix says so.
8. **Money safety**, enforced by the coordinator and persisted in the state repository **before** any call:
   - The worst case (an input-token bound plus `max_tokens`, at the configured price) is charged first.
   - A **daily cap** (UTC day, default $2 as in FREE-02) and a **monthly cap** (default $20, applied to a **rolling 30-day** sum so a month boundary never resets it). Both are CEO-editable through an intent. A call is refused if its worst case would pass either cap.
   - A **rolling 30-day spend log** of every charge.
   - If the pre-charge commit fails, no call is made: the call happens only after the commit that holds the charge succeeded, and only for charges that name this run.
   - The charge is replaced with the actual cost only when the provider reports usage. Otherwise, and whenever the call fails, the worst case stays.
   - A zero price is refused, and so is premium without a price.
9. **Time sources:** the clock for the caps is GitHub's, not the runner's alone:
   - The coordinator reads its own run's `run_started_at` from the Actions API (server time; a re-run attempt has its own).
   - The brain's clock is monotonic: `max(GitHub time, last recorded charge time)`. A replayed or old run can never land in an earlier day.
   - If GitHub's time can't be read, or the runner's clock differs from it by more than 15 minutes, no paid call is made in that run.
10. **Replay and re-run safety:** each request moves `queued → charged(runId) → done | needs_attention`, committed. A `charged` request left by another run (crash, cancelled run, re-run attempt) becomes `uncertain`: its charge stays and it is never called again. The commit's compare-and-swap means two runs can never both charge the same request.
11. **Output stays proposals:**
    - **Plans:** the CEO writes a brief in the game. The answer goes through the strict FREE-02 plan schema and screens (the shared `parsePlan`, invisible-character and heuristic filters, lesson ids limited to the ones given) and becomes a `job_plan` inbox item with every prompt shown. Approving records the decision only; each item is then submitted, if the CEO wants, through the existing paid-job confirmation (`new_job` with `confirmPaid` and the current `configRevision`).
    - **Reviews** of finished cloud jobs and **unblock** suggestions for failed or uncertain ones become `chief_proposal` items. Deciding records the decision only; nothing accepts a job or moves credits.
    - Malformed or unsafe output is needs-attention with the reason; nothing is guessed.
    - Approved lessons from the FREE-07 cloud memory are given to the plan as a delimited data block, and the plan's citations are checked against them.
12. **Prompt injection:** briefs, job evidence and lessons are untrusted data between random per-call markers, with the same rules text as the server.

### FREE-12: outreach email in cloud

13. **Secrets:** the SMTP URL (with its password) is the Actions secret `AGENT_EMPIRE_SMTP_URL` in the state repository. Names are checked only. The sender identity (from address, display name, postal address) is not secret: it is stored in state and printed in every footer.
14. **Every send needs the CEO's approval of the exact message and recipients** (`external_action`): the coordinator freezes a snapshot (subject, body, fixed footer, sender, every recipient, caps) and raises one item whose fingerprint covers it. Any change resolves the item and raises a new one.
15. **Compliance**, as on the server: the fixed footer with the postal address and the STOP line; honest sender identity; one message per recipient, never CC or BCC; a suppression list checked when the snapshot is frozen **and** again right before each send; daily caps.
16. **Pacing:** the coordinator runs every 15–60 minutes, so sends are capped **per run** (default 20) and **per UTC day** (default 50). The game shows the expected delivery honestly: how many runs and roughly how long, given the schedule.
17. **At most once:** before a run sends anything, the tick job claims that run's batch in a commit. The send job sends only the batch claimed by its own run id and writes a receipt. A claim without a receipt becomes `uncertain` and is never re-sent.
18. **Privacy:**
    - Leads and suppression live in the user's private state repository and its git history. A warning at setup must be acknowledged before anything is stored.
    - Store the minimum: email, name, company and tags per lead. Suppression is stored only as salted SHA-256 hashes. The game hashes an opt-out before sending it, so the plain address never reaches the repository through that path. A suppressed lead is removed from the lead list. A finished campaign keeps counts, not addresses.
    - "Delete lead data" writes a commit that removes every lead and every stored recipient address (campaign snapshots and inbox items). The UI says plainly that git history keeps old versions unless the user rewrites history themselves.
19. **Isolation (FREE-04 lesson):** sends happen in a separate `send` job of the coordinator workflow. It holds `AGENT_EMPIRE_SMTP_URL` and no model key, runs only our `send` command, and runs no model or agent code. The tick job, where model output is parsed, holds no SMTP secret. Message content is validated for header injection and size when the campaign is written, when the snapshot is frozen, and again in the send job.
