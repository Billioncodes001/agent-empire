# Names: Agent Empire and the legacy Agent Office names

The product is **Agent Empire**. It began as a fork of [Agent Office](https://github.com/AgentSystemLabs/agent-office), so some internal names still say "office". User-facing text says Agent Empire. "Office" on its own still means the headquarters building, the office host or the office password, for example the offline page's "Can't reach your office host".

The names below stay as they are on purpose. Renaming them would break existing saves, installs, deployments or sign-ins, including the protected development session on localhost:4610.

| Legacy name | Where | Why it stays |
| --- | --- | --- |
| `.agent-office/` | Data folder in each project: `empire.json`, `queue.json`, `config.json`, `devices.json`, `approvals.json`, worker worktrees and more | Every existing save and worker worktree lives here, and the server adds it to `.git/info/exclude` |
| `office/<slug>` | Worker branches | Existing worktrees, PR boards and the artifact importer read these branches |
| `agent-office` bin | `package.json` `bin` (next to `agent-empire`, the same script `bin/agent-office.js`) | Scripts, services and `deploy/provision.sh` installs call it |
| `agent-office.*` keys | Browser `localStorage`, for example `agent-office.profile` and `agent-office.worktree` | The founder profile and per-device preferences survive upgrades |
| `agent-office` / `agent-office-<name>` | `deploy/aws.sh` default deployment name and AWS resource names, plus the security-group description | Existing stacks are found and torn down by these names; AWS security-group descriptions cannot be changed |
| `commonName: agent-office` | Self-signed TLS certificate generated by `src/server/config.ts` | Only identifies the generated certificate; changing it would only trigger needless re-trust prompts |
| Environment variable names | Server and deploy scripts | Existing deployments set them |

The CLI help and error messages print `agent-empire`. Both command names run the same program.
