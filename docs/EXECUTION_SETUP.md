# First-time setup and execution choices

Product decision, 2026-09-27: a VPS is optional. Users bring their own supported provider account/API access and choose where jobs execute. Do not purchase infrastructure by default. Vantage is excluded from all Agent Empire hosting. The first adapter and bundled desktop runtime are implemented. The boundaries below distinguish current behavior from the remaining cross-device work.

## Setup flow

1. Create the character and choose the founding buildings. Keep existing defaults and funded-workstation rules. Allow exploring the locally installed world before connecting a provider; pending AI work must stay visibly pending.
2. Connect GitHub and select specific repositories. Explain branch/PR permissions and keep changes separate from the default branch until reviewed.
3. Connect one or more AI providers. Present official browser sign-in only where the integration supports it; otherwise offer a provider API credential through protected desktop/server storage. Never request the user's account password, reuse another application's session cookies, or assume subscription login grants general API access.
4. Choose execution: provider-hosted cloud sessions (target default), supported GitHub task workflows, this computer, or the user's own Agent Empire VPS. Validate the provider/account/environment combination before enabling jobs. API model access alone is not proof of a hosted executor.
5. Set real-money controls: maximum concurrent jobs, per-job allowance, daily allowance, time limits and action approvals. Label estimates and provider-enforced limits separately. In-game worker capacity and credits must never imply unlimited real compute or pay API charges.
6. Show a review of the repository, provider, execution location, billing owner, permissions and closure behavior. Connection checks must not silently start a paid task. Submit a user-authorized test only with its explicit cost boundary.

Local execution continues only while the local runner remains active and awake. Provider-hosted and VPS tasks continue independently of the game client, subject to service limits, approvals and failures. Keep the mode selectable later, without implying an active process can migrate between hosts.

## Provider capabilities checked

- Anthropic: Claude Managed Agents (beta) provides managed cloud sandboxes, autonomous tool execution and persisted sessions/events. It uses Claude Platform access. This is distinct from a plain Messages API request and from a Claude consumer subscription. [Overview](https://platform.claude.com/docs/en/managed-agents/overview), [quickstart](https://platform.claude.com/docs/en/managed-agents/quickstart).
- OpenAI: Agents API exposes a managed Codex harness with session orchestration/recovery and a choice of execution environment, including OpenAI-hosted sandboxes. Model, tool and sandbox usage are billed separately according to API pricing. [Overview](https://developers.openai.com/api/docs/guides/agents-api/overview).
- Codex product login: official Codex clients support ChatGPT subscription sign-in and API-key authentication for local work; Codex cloud requires ChatGPT sign-in. This does not establish an embeddable third-party OAuth flow for Agent Empire. Do not present one until documented integration support is verified. [Authentication](https://learn.chatgpt.com/docs/auth).
- GitHub: Copilot cloud agent and Actions-backed agentic workflows are possible task executors, subject to account access, permissions and usage limits. Agentic Workflows is in public preview. [Cloud agent](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent), [workflows](https://docs.github.com/en/copilot/concepts/agents/about-github-agentic-workflows).

Only the Anthropic Managed Agents adapter is merged in Agent Empire. **OpenAI status (2026-10-23):** an OpenAI Agents adapter for cloud mode (CLOUD-06, [plan](team/CLOUD_06_OPENAI_PLAN.md)) is built on the unmerged branch `claude/cloud-06-openai`. It is unreviewed and parked: it is a paid provider, and the owner's free-first direction (`team/FREE_STACK.md`, in progress) now has priority. It is not in any build. GitHub workflow executors are not implemented. These provider surfaces are not a guarantee of access on every user account. Recheck availability and authentication before implementing each adapter. A provider login/API key never means unlimited agents, unlimited tokens or unlimited runtime.

## Task and synchronization contract

Create and persist a stable logical task ID before dispatch; record executor, provider session ID, source commit, branch, event cursor and cost evidence. Model states must distinguish queued, dispatch uncertain, running, waiting for approval, completed, failed and cancelled. Never retry an uncertain dispatch blindly: reconcile with provider state or require a decision when the provider offers no idempotent creation. Switching providers must not duplicate an active task.

Dispatch when the user assigns work, not on an app-close callback. Desktop crashes, lost connectivity and phone suspension must not lose already accepted jobs. An offline assignment can be saved locally as not submitted; dispatch only after reconnection under the selected approval policy.

On reconnect, fetch provider events and GitHub results from the last acknowledged cursor, update reports from evidence and reconcile task IDs before applying rewards. Cloud jobs must use their own execution credentials; no required tool may depend on the closed desktop app remaining reachable. Persist outputs to the authorized branch/PR and recoverable artifact store before disposing of a sandbox. Provider retention, account limits and approval pauses remain visible.

Reuse the existing hash-verified isolated importer where its artifact contract applies. GitHub branches and provider artifacts need adapters rather than pretending to be the existing host endpoint. Preserve dirty local files and require review before merging. Resolve city-save conflicts separately from repository code; choose and implement a durable cross-device save service instead of assuming GitHub source history stores all game state.

## Offline and credential boundary

Desktop now packages the game assets, server and local simulation/save support. It opens an existing Git root or initializes an empty city folder, binds only to loopback and keeps the same local port for browser profile persistence. Git must be installed. The web PWA still only provides a public offline explanation page; it does not cache the playable world. Web/mobile assets may be cached independently, but provider keys, private terminal content and authenticated API responses must not enter public/offline caches.

The native launcher encrypts Anthropic and GitHub credentials with Electron safeStorage backed by the OS credential store. It rejects unavailable or plaintext-only storage. Hosted deployments read ANTHROPIC_API_KEY and AGENT_EMPIRE_GITHUB_TOKEN from their protected environment. Never enter credentials in chat. The GitHub token is sent to Anthropic when an explicitly submitted session mounts the selected repository; use repository-scoped permissions. Saving credentials or setup does not dispatch work. Web/mobile need a supported short-lived authorization flow or a managed backend with protected credential storage. Such a backend can be serverless and does not require buying a VPS, but is still infrastructure we must implement. Do not copy raw API keys into browser localStorage, Git, game saves, logs or synchronization artifacts.

Provider-hosted execution should be the initial adapter milestone. Retain the existing single-host/VPS transport as an optional path and local execution for users who prefer it. No new provider session, account connection, infrastructure purchase or credential migration is authorized merely by saving these setup preferences.

## Implemented adapter and limits

In Settings → App & connection, open execution setup. Choose Local, an existing VPS, or Anthropic cloud. Cloud setup requires an existing Claude Platform agent with the managed toolset, a cloud environment, and optional vault ID. In this host execution setup, provisioning those resources and GitHub OAuth are not implemented. Cloud mode (the GitHub state repository) differs: its coordinator finds or creates the agent and environment itself with the ANTHROPIC_API_KEY Actions secret (see [cloud-exec-setup](team/reports/cloud-exec-setup.md)). The connection check reads their metadata and the selected GitHub repository/branch; it does not launch a session or guarantee write access. It expires after five minutes or a configuration/credential change.

Cloud tasks have a separate review-and-submit flow. The server stores dispatch intent and a full budget reservation before POST, pins the source commit and assigns a task branch. A lost creation response remains **dispatch uncertain**, with no blind retry. Known sessions can be polled after restart; unknown/idle/approval-paused jobs retain capacity. Provider idle is not verified completion. Stop explicitly interrupts and archives; if interruption is still settling, refresh and stop again once idle. Without a returned session ID, inspect the provider Console using the task ID before resolving an uncertain dispatch.

Limits are 1–10 concurrent cloud tasks, a per-task allowance and a daily UTC reservation allowance. Full reservations are retained for the day, with unresolved earlier tasks carried forward. Provider budgets are evaluated between requests and may overshoot; these controls are not account-wide billing caps or unlimited usage. No wall-clock cutoff is implemented. Approvals remain in the provider Console.

The bundled desktop starts its local task queue paused at zero concurrency. Completing local setup does not start founding briefs; set queue concurrency explicitly to start them. Local workers stop when the native app exits. Provider-managed sessions already accepted continue independently, subject to provider limits. Switching execution mode cannot migrate jobs, and active or uncertain work prevents conflicting changes.

The adapter stores task status, session ID, source commit, branch, event cursor and observed cost. It does **not** yet verify or import provider outputs/PRs, attach cloud jobs to civic workers, award completion revenue, synchronize city saves across devices, or provide browser-only credential hosting. The existing single-host Git-bundle importer remains separate. Web and the bundled mobile/desktop apps can control an authenticated running host; a laptop hosting that connection still has to stay online. Cloud mode (first-launch setup) is the alternative that keeps running with every app closed.

Automated adapter tests use an injected fake transport. `npx tsx tools/execution-fixture.ts` starts a disposable UI fixture on port 4617 with password `execution-qa-only`; every provider request is intercepted and real workers are disabled. It is not evidence of a paid provider session succeeding.

## Cloud mode in GitHub Actions (FREE-04)

Cloud setup offers three engines: **Free · Qwen Code**, **Claude subscription**, and **API keys** (today's Anthropic Managed Agents path, unchanged). The first two run each job as one `workflow_dispatch` run of `.github/workflows/agent-empire-job.yml`, which setup commits to the project repository. The coordinator starts and polls runs with `PROJECT_GITHUB_TOKEN`, which then also needs **Actions read/write** on the project.

- **Free:** Qwen Code 0.25.0 (npm tarball checked against its pinned sha512). Model source, in order: your self-hosted runner with Ollama (by label), a free hosted key you opt into (`FREE_LLM_API_KEY`, with a data-use warning), or `qwen2.5-coder:1.5b` on CPU (about 986 MB plus a checksum-pinned 1.5 GB Ollama download per run; slow; trivial tasks only). Cost US$0; no money is reserved, the caps are the run's time and turn limits.
- **Claude subscription:** `anthropics/claude-code-action` pinned by commit SHA, with `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`. You run `claude setup-token` and `gh secret set CLAUDE_CODE_OAUTH_TOKEN --repo <owner>/<repo>` (or `/install-github-app`) in **your own terminal**. The Empire has no field for the token and only checks that the secret's name exists. It reminds you to rotate it after 11 months. Jobs show "billed to your Claude plan", never a US$ figure. An `ANTHROPIC_API_KEY` secret works too; those jobs show Claude Code's own cost estimate.

Standard GitHub-hosted runners are free in public repositories. Private repositories use your plan's included minutes; a self-hosted runner uses none. Details and the first-real-run checklist: [reports/free-04.md](team/reports/free-04.md).
